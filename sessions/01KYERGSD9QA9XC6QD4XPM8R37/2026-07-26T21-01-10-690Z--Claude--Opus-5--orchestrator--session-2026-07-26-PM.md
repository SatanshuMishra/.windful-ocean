FAILED / NOT DONE, and why
- b0e1079 was NOT merged, NOT pushed, NOT published, NOT installed. Security review returned BLOCK. Decision 0011. On a 55-command corpus, 20 commands the old 0fe1c02 guard DENIED are ALLOWED by the branch, against only 3 true positives gained. The orchestrator independently reproduced 12 of 12 headline regressions against the real module. Decisive shapes: `sudo rm -rf <root>` ALLOW, and `( rm -rf <root> )` ALLOW - wrapping any blocked command in one pair of parens defeats the guard. Others: bare `&` is not a segment separator so `true & rm -rf <root>` is swallowed into the first segment; `{ ...; }` groups; prefixes env/command/timeout/nohup/time/exec/!/FOO=bar/then/do; `$'...'` and `$"..."` mis-lex to a corrupted token; find -exec rm, xargs rm, git -C <root> rm; option-attached paths dd of= and cp --target-directory= are filtered out as flags.
- Root cause is architectural, not a list of gaps. pre-tool-use.mjs decides allow-unless-provably-destructive over a hand-rolled bash parser, so every parse gap is a silent evasion and the failure mode is silent destruction of the ledger. The blunt 0fe1c02 substring matcher over-blocked but resisted evasion; precision without inverting the default traded evasion-resistance for ergonomics.
- Also surfaced, not blocking this merge: scanSegments is quadratic in tokens per segment (128k tokens = 15.2s) against a 10s hook timeout, so the guard fails OPEN under a large single-line command; any size cap added must fail CLOSED. cd - / pushd / subshell cwd desync in both directions. git clean -fdx and git checkout -- destroy ledger content without touching the ref, so they sit outside the accepted ref-level carve-out. The bare mcp__ledger__* auto-allow is over-broad for a public plugin and fires before roots are resolved.
