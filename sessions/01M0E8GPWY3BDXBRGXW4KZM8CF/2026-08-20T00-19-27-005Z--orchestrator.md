Checkpoint written mid-session while the architect dispatch is still in flight. Nothing has been implemented; no repository file has changed.

## What was asked

Three goals for the centralized PR tool, in the owner's words. First, the body must lead with what the change is, then move to other details. Second, the body must be human-friendly: clear, concise, assuming no domain understanding, with file names and internal record numbers kept out unless there is a very specific reason, and proper sentence structure enforced. Third, all AI, agent and model attribution must be removed and reliably blocked, because every pull request is opened on the owner's behalf regardless of who typed it.

Binding constraints on any solution: robust and simple, never complex and fragile; no heuristic pattern matching standing in for judgment; no infinite edge-case plugging; clear goals declared, then implemented, with scope held.

## What was established

Two read-only audits ran. Their conclusions, which the SPEC should not re-derive:

The tool is sound in kind and should not be replaced by prose. Instruction-following collapses under multi-constraint load, a generator needs one grammar where a validator needs two, and the anti-forgery property is unreachable by instruction. Nothing external requires AI attribution.

Almost every change lands in one pure file, the format module, and is a deletion or a reorder rather than an addition.

The single real coupling is that the trailer text doubles as the reuse-detection key. Deleting it without a replacement reports every reused pull request as unverified and parks the shipping engine. The replacement available is a structural check on the tool's own heading skeleton, which names nothing and is unforgeable because the value sanitiser already refuses any caller value beginning with a hash. That same check is what the missing continuous-integration boundary validator would need, so one mechanism serves both.

The readability goal is largely not a tool defect. The tool injects only its headings, two line prefixes, a size warning, a supersedes link and a depends line carrying internal unit identifiers. Everything else is verbatim caller text, and the callers are where the jargon originates. The value sanitiser rejects nothing readability-related and never will; that rule belongs in the prose layer beside the honesty rule.

Ordering is a house-style call. No study measures it. The owner's chosen order is authoritative and was not relitigated.

## What was decided

Decision 0631 records the removal of all attribution, knowingly reversing decision 0597 and superseding two clauses of the centralisation spec.

## Where it stands

An architect dispatch is composing the specification. It must decide the exact skeleton, the reuse detector contract, whether the origin flag survives, the sentence-form rule and which fields it binds, the fate of the size warning and the depends line, and which of the four known gaps are in scope versus filed. It was told to bias toward filing and to declare the unenforceable readability goals as non-goals in writing, so a later session cannot reopen them as unfinished work.
