=== THE THREE APPROACHES PUT TO THE USER (step 4), awaiting a pick ===
A, RECOMMENDED - immutable release subtrees plus an atomic pointer swap. ~/.claude/current -> releases/<sha>, built by `git archive <ref> .claude | tar -x`; each live entry (skills, agents, lib, workflows, hooks, rules, docs, CLAUDE.md, keybindings.json) links through current. Promotion is one ln -sfn. The live ref is recorded, so drift is `git diff <live-ref> HEAD -- .claude` - git-native answers without git-native machinery.
B - a git worktree per release, pointer-swapped. Same atomicity and promotion history is the reflog of refs/config/live, but a worktree materializes the WHOLE repo not the .claude subtree, each registers in .git/worktrees needing pruning, and it collides conceptually with the .claude/worktrees/ mitosis already owns. Promoting instead by `git -C live reset --hard` forfeits atomicity outright.
C - converge in place into a single live tree. Real copies instead of symlinks-into-the-working-tree; promotion is an idempotent manifest-driven sync from a pinned ref with a LIVE_REF marker. Simplest model, maximally NON-atomic: promotion tears the live tree file by file, which is the hazard rather than a fix for it.
RANKING ARGUMENT, and it survives the unmeasured question: if swaps are invisible mid-session, A and B are clean and C is strictly worse; if swaps are live, A and B still give file-level consistency where C tears mid-file. So the open measurement changes the promotion-timing CONTRACT, not the choice of approach.
DEFERRED TO STEP 5 as their own design sections, because they are orthogonal to the A/B/C pick: the ENFORCEMENT mechanism (sync as a convergence check called from SessionStart, Stop and mitosis Ship, so it cannot be missed the way an event handler can) and the settings.json TWO-WAY reconciliation, with the leak gate applied to the CAPTURE direction only, since live-to-repo is the only direction that can push content into a public repo.
