THREE BLOCKERS AGAINST THE ARCHITECTURE AS LITERALLY DESCRIBED.
1. A Workflow cannot ask a human. Documented at code.claude.com/docs/en/workflows: "No mid-run user input... Only agent permission prompts can pause a run. For sign-off between stages, run each stage as its own workflow." Workflow resume is also same-session-only, so a rotated orchestrator cannot re-enter a running workflow.
2. Nothing inside Claude Code reads a spawned subagent's context fill - not hooks, not transcripts, not /context. The 30% rotation trigger had no sensor. Only an Agent SDK host sees ResultMessage.usage.
3. Subagent nesting caps at 3 layers below main (CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH); main -> orchestrator -> phase -> worker exhausts it and workers cannot fan out. An OS-process supervisor resets the count.
All three share one cause: the Workflow sandbox is the wrong host for an orchestrator. Hence 0325.
