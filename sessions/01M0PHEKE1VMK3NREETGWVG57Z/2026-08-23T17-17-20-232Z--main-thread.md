## The receipts finding, read from the enforcer source

The block was never really about configuration. The enforcer classifies a file as production source unless it matches a hardcoded doc-or-meta pattern covering markdown, text, the .github directory, receipts.config.json and .gitignore. A .toml file misses that pattern, so the config-only pass branch cannot fire. package.json, tsconfig.json and any yml outside .github are classified the same way.

Two consequences worth carrying forward. A work-type of chore or refactor is a REAL pass, not a ladder downgrade: it inverts the receipt to a full suite run on head that can itself block, and six of the eight re-run gates execute rather than two. The accepted work-type set is NOT closed, the regex is unanchored and matches mid-sentence, and declaring an inert value such as docs or config is worse than declaring nothing because a truthy work-type disables the config-only escape. No config key scopes which paths require a receipt; the claim block accepts exactly four keys.
