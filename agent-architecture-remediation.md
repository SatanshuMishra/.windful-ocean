## Decisions in force

- D1 Invert the delegation default: main works, delegation is the exception: Inverted. delegation-discipline.md is deleted and replaced with four named reasons to delegate, which map one-to-one onto the five retained agents so the roster itself is the structural half of the pairing. A routing mistake now fails toward "main did it itself", which is cheap and usually correct. This makes routing accuracy non-load-bearing rather than attempting to make routing accurate — a routing agent was rejected because it adds a new advisory layer for a decision that cannot be made deterministic.
- D2 Cut the roster from 13 to 5; collapse three maker personas into one machinist: Five: code-reviewer, security-reviewer, conformance-auditor, researcher, machinist. Revision 1 of the SPEC deleted the maker entirely and that was wrong — isolation worktree, routing to a cheaper model, and tool restriction are available only to a cold subagent and never to a fork, which has no frontmatter and inherits main's model and tools. implementer, test-engineer and platform-engineer were three personas of one job, so they collapse into one vehicle. The name machinist was chosen because it describes how the agent works (to a finished drawing, adding no design judgment) rather than what it knows, which is the line between a legitimate role and the expert-persona anti-pattern.
- D3 A correctness gate asserts a categorical property; only a circuit breaker may carry a threshold: Adopted as SPEC section 0.3 and audited across every mechanism. It removed the brief-length gate and also caught maxTurns, which had passed unexamined as a tuned number. maxTurns survives only as an admitted circuit breaker with values re-derived from measurement: read-only agents observed a legitimate maximum of 115 turns and are set to 300; machinist observed 598 and is set to 800; the runaway that motivated the cap ran 1,184 turns. The three surviving hooks all assert categorical properties — sleep inside a loop, a path matching a task output file, a nesting depth of one.
- D4 Replace the brief-length gate with per-agent entry invariants: Each agent's first returned field is its own precondition, proven with a command and its exit code, and the agent halts rather than proceeding when the check fails. code-reviewer proves a non-empty diff exists; conformance-auditor proves both a named standard and a named artifact resolve to real paths; machinist enumerates and counts the files its brief names and halts at a count of zero, because a brief that cannot name its targets was not fully specified. A wrong dispatch is therefore discovered in the agent's first action rather than after three rework rounds. The residual risk — that a cold dispatch which should have been a fork still proceeds — is recorded as accepted in SPEC section 10.1 rather than papered over with another advisory rule.
- D5 Prohibit capability claims in configuration entirely: Prohibited, as a standing clause in CLAUDE.md. A capability claim is a cached fact about a system that updates independently, with no expiry mechanism and no way for an agent to falsify it from inside — which makes it self-sealing. Correcting the sentence was rejected because the next harness update makes it false again with nothing to catch it, and a review cadence is itself advisory. Configuration now states preferences, constraints, and facts about this project that the harness cannot know; the harness describes itself at runtime, accurately, for free. Acceptance check 8.4 greps for the claim shapes and must return zero.
- D6 Procedure lives in skills, not in agent bodies or always-on rules: Procedure moves to skills. Retained agents carry role, entry invariant, output format and stop conditions only, pulling procedure via the skills: frontmatter field, which injects full skill content at startup. Four new skills are created from surviving procedure (writing-tests, committing-work, reviewing-code, research-citations); five deleted agents produce no skill at all because their content was persona or duplication. Five always-on rule files move into skills and seven are deleted outright, cutting the preamble from about 12,935 to about 2,520 tokens. Constraint recorded: a skill with disable-model-invocation true cannot be preloaded into a subagent, so any skill named in a skills: field must leave that flag unset — acceptance check 8.7.

## Open risks

- R1 The .windful-ocean repo is PUBLIC and the logbook ledger is pushed to a _ledger branch on its origin. The confidential project codename that appears in the incident transcript paths must never be written into any tracked file, decision record, session entry or artifact pointer. Refer to the incident only by session uuid cfdbeee9.
- R2 Routing cannot be made deterministic. With the brief-length gate removed there is no categorical check that stops a cold dispatch which should have been a fork; SPEC section 10.1 accepts this because the default now fails toward main doing the work and the entry invariant makes a wrong dispatch halt loudly.
- R3 maxTurns is a threshold and is admitted as such. Its values are measured rather than chosen, but if a legitimate agent ever hits one the value is wrong and must be re-derived from observation, never overridden case by case.
- R4 Agent definition edits do not reach dispatches made in the same session: disk showed 14 sections while a dispatched agent reported 13. Any acceptance check that dispatches a just-edited agent tests the previous definition. Restart before verifying criteria 9, 10 and 11.
- R5 The acceptance checks in SPEC section 8 prove the configuration is applied, not that it is better. Proving improvement needs a comparable unit of work run afterwards, measured on agents per unit, wall-clock per unit, and peak main-thread context.
- R6 Output-format compliance beyond the first field is advisory. Nothing enforces that an agent fills its sections honestly; the only mitigation is that a work-forcing field cannot be filled without doing the work.
- R7 Fork is gated by a server-side feature flag, not by entrypoint. The binary carries isForkSubagentEnabled and tengu_fork_subagent_enabled. Probed in the desktop app: a fork dispatch fails hard with "Agent type 'fork' not found". No env var, settings key or local statsig cache exposes or overrides it. It cannot be switched on in desktop or off in CLI, and can flip either way with no release and no config change. A routing rule naming fork is a prose claim about a flag nobody here can read or set.
- R8 Dropping fork (option A) works against the SPEC's own primary objective. Section 1.3 names main-thread context occupancy as what this remediation reduces, and fork is the only vehicle that reduces it without a re-typed brief. Under option A, step-dependent high-volume work floods main on both surfaces and the fallback is harness summarization - a fidelity loss rather than a failure. No portable substitute exists: Explore is cold and does not carry the conversation.
- R9 BLOCKER B2: thread criterion c4 globs ~/.claude/rules/common/git/*.md, a directory step 8 empties. The glob then matches nothing, the shell passes it literally, and cat exits non-zero rather than returning a byte count. Amend c4 at step 10 to drop the git term, matching check 8.5. Do not leave a placeholder file in the directory to keep the glob alive.
- R10 Compressing security.md and rescoping no-direct-db-access.md narrows what is always-on, with two gaps open by choice. vibesec triggers on web application code, so a non-web project gets no depth from it; mitigated by preloading vibesec into security-reviewer, which is dispatched regardless of project type. And block-destructive-bash.sh matches the Supabase CLI path only, not psql or a raw DATABASE_URL, so the general prohibition stays prose rather than deferring to the hook.
