# 0197. M4 deletes the durable window state all the way down; one constant governs build-ahead width and the cap becomes a pure function of the invocation

## Context

0196 left the resolveRunIdentity window carry-over (mitosis.js:722, twin in recovery.mjs, pinned by recovery.test.mjs:639 'the persisted AIMD window is carried') deliberately open, because the code gives no signal whether it dies with AIMD or survives to persist an engine-arg override across relaunch. Two adjacent calls were left open with it by implication: WINDOW_FLOOR's fate, since 0196 established it is NOT pure AIMD plumbing but also leases.mjs:111's generic buildAheadWindow fallback when windowSize is not an integer; and whether nextW survives in planReconcile's return shape, since reconcile.test.mjs:208-209 and :227 deepEqual the whole returned object and break on dropping it despite not being AIMD tests. The measured reader set is the deciding fact: the carried manifest.window feeds exactly two consumers, clampWindow at mitosis.js:4253 and planReconcile's persistedWindow read at :2990 / reconcile.mjs:104, and M4 deletes both. Spec section 3.3 replaces the entire WINDOW_FLOOR/WINDOW_CEILING/WINDOW_INCREMENT vocabulary with one constant, BUILD_AHEAD_CAP = 8, with an optional engine-arg override and the constant as the default.

## Options

- Delete the carry-over, delete WINDOW_FLOOR in favour of BUILD_AHEAD_CAP, and drop nextW from planReconcile's return shape - the durable window state dies entirely
- Keep the carry-over so an engine-arg override persists across relaunch, and keep WINDOW_FLOOR as a non-AIMD default
- Keep nextW in the return shape hardcoded to BUILD_AHEAD_CAP so no deepEqual expectation has to change

## Outcome

THE DURABLE WINDOW STATE DIES ENTIRELY. The cap becomes a pure function of the invocation - the constant, or an engine arg supplied by that caller - and is never read back from durable state. Three consequences bind M4. (1) The carry-over at mitosis.js:722 and its recovery.mjs twin GO, and recovery.test.mjs:639 goes with them; recovery.test.mjs:600 ('a top-level window is rejected') SURVIVES untouched, because PUBLISHED_RUN_FIELDS excluding window is an independent invariant that section 12 item 5 protects regardless of AIMD. (2) WINDOW_FLOOR GOES and leases.mjs:111's fallback re-derives from BUILD_AHEAD_CAP, moving that fallback 3 -> 8. That is a real behavior change and it is the INTENDED one: a floor of 3 surviving beside a cap of 8 would preserve half the deleted tuner's vocabulary and leave two authorities for one width. (3) nextW is DROPPED from planReconcile's return shape rather than hardcoded, and the three reconcile.test.mjs deepEqual expectations are updated; a field that always equals a constant is dead weight that invites a future second authority. REJECTED persisting the override, on the Quality pillar and on two ratified invariants: section 3.1 derives state from facts rather than folding it from the journal, and section 3.6's invoker model - ratified as section 13 item 2, one idempotent command with three callers - means each caller supplies its own args. A relaunch that silently inherits a cap the operator never passed is precisely the surprise that model forbids, and it would restore the second-authority shape section 12 item 5 names as the invariant to protect. TWO PRECONDITIONS THE IMPLEMENTER MUST DISCHARGE BY MEASUREMENT, NOT ASSUMPTION, because this decision rests on the grounding pass rather than on first-hand grep. Before removing the carry-over, prove by exhaustive grep that manifest.window has NO surviving reader once clampWindow and persistedWindow are gone; a surviving reader refutes this decision rather than being worked around. And before deleting applyRunDelta's 'window' record kind (mitosis.js:815-829 / run-log.mjs:35-49, whose only producer persistWindowCheckpoint M4 deletes), prove by execution what the fold does with an UNKNOWN record kind: .mitosis/ is gitignored and per-machine, so a journal written before M4 exists on this machine and will still carry 'window' records. If unknown kinds are inert the case is deleted as dead code; if the fold throws or mis-folds, the case STAYS as an explicit ignore and the reason is backward compatibility, stated rather than silent.
