# 0294. Round 4 fixes against a stated control-file contract, because four of five blockers share one root cause and a reviewer's own fix was over-strong

## Context

Round 4 of hardening the cutover unit ran as an independent review under a dedicated owner agent: four reviewers (two code-reviewer, two security-reviewer), unanimous BLOCK. The round-3 numbers all reproduced under independent measurement (146/0 config tests, 2116/0 full suite, invariant gate exit 0), so the numbers were never the problem. Five blockers stand: a crafted CUTOVER journal plants an arbitrary symlink at any config-root entry including ~/.claude/hooks (code execution); entry.aside is trusted by containment only, so rollback relocates arbitrary content and reports success; a planted ~/.claude/LIVE receipt silences protect-claude-config.sh for repo-path guardrail edits, a security regression this diff introduces into an existing guardrail; already-linked decided by realpath equality leaves the entry dangling; and git -C receipt.repo_root is validated only as a non-empty string. A stale invariant-coverage record whose M5 row falsely self-certifies sits behind them, plus eight MEDIUMs. The owner agent fixed nothing, deliberately. Two facts drove that. Four of the five blockers share one root cause - the journal and the receipt are unauthenticated, ungated control files, so anything that can write them steers privileged filesystem operations. And one reviewer's recommended fix for the top finding was itself over-strong: containment-checking entry.target before restoring a prior link would refuse every legitimate rollback, because the prior target of a pre-cutover entry is legitimately outside the config root - ~/.claude/agents, skills, lib, docs and notes were confirmed to be exactly such symlinks. Implementing the reviewer reports unadjudicated would have shipped 0293's failure mode a second time in the same unit.

## Options

- Design the authenticated, gated control-file contract for the journal and receipt first, then implement one fix round against those stated invariants - ADOPTED on the user's explicit choice. Dispatch a fix round directly against the five blockers and eight MEDIUMs as listed - rejected: that is the shape of rounds 1-3, each of which introduced a new defect on a path nobody had named, and it would have carried the over-strong entry.target fix into the code. Reconsider the unit's scope, on the theory that 785 lines carrying containment, journaling, rollback, notes migration and receipt handling in one irreversible verb is too large a surface - rejected for now, not on the merits but because the root cause is now named and a contract-level fix is the cheaper test of whether the surface is really the problem. Stop and hand off to a fresh session - rejected: the review is fresh and the root cause is identified, so the context is worth spending now.

## Outcome

Adopted. A read-only design pass (solution-architect) evaluates 2-3 designs for authenticating and gating the journal and the receipt, and states the result as testable invariants that a single subsequent fix round implements. Each invariant must name both what it forbids and what it must continue to permit, and must be validated against a realistic pre-state - a live tree whose depth-1 entries are already outward symlinks. An invariant with no stated permit-set is not finished. This is the direct operational consequence of 0293, now that the same failure mode has appeared three times in this unit: round 2 too weak, round 3's written correction too strong, and round 4's reviewer proposal too strong again. The recurrence is the argument: reviewers reliably find the weakness and unreliably price the permit-set, so adjudication against a stated contract is the control, not more review. The already-linked/dangling blocker is explicitly OUT of the contract's scope as a separate contained fix (derive created from linkTargetFor(name) rather than reading it), so it is not folded into a design question it does not belong to. Separately and in parallel, the c3 Stop-path defect found this round - converge.mjs Stop writes to stderr with exit 0, so a Stop-triggered promotion, a real live mutation, reaches neither model nor user - is fixed in this branch under a hard scope fence limiting it to converge.mjs and its test, since it is independent of the control-file root cause and gated behind nothing. Nothing was committed, pushed, or PR'd this round, and no live write occurred.
