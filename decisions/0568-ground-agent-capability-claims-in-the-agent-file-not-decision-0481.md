# 0568. Ground every claim about an agent capability in the agent file on disk, never in decision 0481

## Context

U6.2 rewrote three references that had routed through the deleted report skill, sending them to technical-writer instead. All three described HOW technical-writer delivers: research.md:33 said it "preloads visual-explainer", agent-gap-audit/SKILL.md:26 said to dispatch it "to render the report", and CLAUDE.md:13 implied it produces the rendered artifact. All three are false against .claude/agents/technical-writer.md as generated by wave 4. That file has no skills frontmatter field at all, so nothing is inlined at spawn; visual-explainer reaches it as a generated body pointer at line 38, because decision 0503 routes any skill at or above 4 KB to a pointer and visual-explainer is 6,743 bytes. Its tools line grants no Skill tool, so per SPEC section 3 platform fact 2 it receives no skill content and cannot invoke one. Its own body disclaims rendering outright. The wording came from decision 0481, which reads "technical-writer preloads visual-explainer only and writes report content directly" - accurate when written on 2026-08-16, superseded the next day by 0503's preload-versus-pointer split, and never amended because decision records are write-once by design. The retirement census cannot catch this class of error: it counts occurrences of nine literal names and has nothing to say about whether a sentence naming a surviving agent is true.

## Options

- Ground capability claims in the agent file on disk and correct the three lines
- Keep decision 0481's wording, since it is the ratified source for the report-skill withdrawal
- Edit technical-writer.md so the prose becomes true

## Outcome

Every claim about what an agent preloads, holds, or can do is grounded in that agent's file on disk at the head commit, never in a decision record's prose about it. The three lines were corrected within U6.2 rather than filed above the ceiling, because U6.2's declared criterion already required every rewrite to be true of the post-change configuration, making this a defect in the deliverable rather than a discovery above it. Editing technical-writer.md to match the prose was rejected outright: .claude/agents is byte-identical by U6.2's no-collateral assertion, agent bodies are generated artifacts owned by waves 4, 5 and 7, and changing an agent to validate a sentence inverts the direction of truth. The general lesson is that a decision record is write-once and therefore ages: 0481 remains correct about WHAT was withdrawn and stale about HOW the replacement is delivered, and only the file system distinguishes the two. Filed above the ceiling and not fixed: technical-writer.md's body still says the dispatching skill owns rendering and placement, which no longer names anything now that the report skill is deleted.
