# 0714. The missing modules are carried as their own unit, and the set is six rather than the seven first reported

## Context

The user directed that the modules the import closure missed be carried as a unit ahead of the suite unit. Scoping that unit exposed the seven-module figure as an artefact of a blind instrument. The four-form closure scan does not see a module loaded as a spawned driver, and the subsystem root is reached only that way, through a file URL built from the module's own location and handed to a synchronous spawn. It was therefore invisible to the original import closure, which is why it was never carried, and invisible to the scan that produced the seven. Re-running the census over every path-shaped string literal rather than over load syntax returned thirteen references across nine distinct modules.

## Options

- Carry all nine candidates the corrected census returned
- Carry only the six that form the closed subsystem, and leave the three the disposition table assigns to the host
- Carry the seven originally reported

## Outcome

Six are carried, forming one connected subsystem whose transitive closure terminates at twelve files with the other six already present, six hundred and fifty-three lines in total. Three are not: the ledger linter, which the plan's own disposition table assigns to the host and which no production code reaches; a classification module belonging to the observer-audit tree rather than the engine; and an analytics module that is not a reference at all, but a string key inside a documented exception table in a test the census unit already deletes. Carrying all nine as first instructed would have pulled two host-classified modules and one non-reference into a public engine plugin while still missing the subsystem root. Two consequences are filed rather than fixed: the subsystem root falls back to the home directory at one site, which the hermeticity unit forbids and must absorb as a signature change, and the ledger linter's test is now the only genuinely orphaned test, recorded under the census unit's existing count-divergence convention. The generalizable rule: a closure is computed by enumerating every path-shaped literal and classifying each, never by matching the loading forms currently known.
