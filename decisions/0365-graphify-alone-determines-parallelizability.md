# 0365. Graphify alone determines parallelizability; the confirm-cuts oracle pass is cut

## Context

0364 split the authority the 2026-08-11 directive had assigned wholly to graphify: graphify owned surfaces, clusters and file scopes, but the cut-edge set got one bounded LSP oracle confirmation inside Decompose (stage S4 CONFIRM CUTS) before the partition sealed. It was recorded but never user-ratified. Its counter-evidence was a single measurement of Graphify 0.9.1 on a TypeScript project while the installed build is 0.9.5 and this repo is mixed-language.

## Options

- Keep 0364: graphify owns surfaces and scopes, a bounded oracle confirms only the cut-edge set inside Decompose
- Graphify alone, with no confirmation pass at plan time
- The LSP oracle alone, with graphify used only to orient

## Outcome

Graphify alone. 0364 is superseded and the S4 CONFIRM CUTS stage is cut from the Decompose pipeline. The user's ruling: graphify is used FOR robustness, speed and efficiency together, and if the graph is current then its file relationships are trusted as correct — spawning agents and spending tokens to re-verify them defeats the reason graphify is in the design at all. The residual no static map catches is covered where it was always covered, at merge time by the green-branch invariant and the composed D6 check, not by a second plan-time pass. The seam 0364 was deliberately kept clean now collapses back to graphify-alone as designed.
